## ADDED Requirements

### Requirement: Стартовые данные и сводка

Трекер MUST при запуске со стартовым примером показывать задачи «Чтение»
(2 ч, выполнена), «Практика» (4 ч, активна) и «Повторение» (2 ч, активна).

#### Scenario: Стартовый пример

- **WHEN** трекер запускается со стартовым примером
- **THEN** общее время составляет 8 ч, выполнено 2 ч, прогресс составляет 25%.

### Requirement: Изменение задач

Трекер MUST добавлять новую задачу после успешной проверки формы, удалять
выбранную задачу и переключать `done` выбранной задачи. Эти действия MUST
изменять данные и обновлять видимый список и сводку.

#### Scenario: Добавление корректной задачи

- **WHEN** пользователь вводит название «  Конспект  » и 0,5 ч и отправляет форму
- **THEN** в данных появляется активная задача «Конспект» на 0,5 ч, а общее
  время увеличивается на 0,5 ч.

#### Scenario: Выполнение «Практики»

- **WHEN** в стартовом примере пользователь отмечает «Практику» выполненной
- **THEN** её `done` становится `true`, выполнено 6 ч из 8 ч, прогресс составляет 75%.

#### Scenario: Возврат «Практики» в активные

- **WHEN** пользователь снимает отметку выполнения с «Практики» после
  предыдущего сценария
- **THEN** её `done` становится `false`, выполнено 2 ч из 8 ч, прогресс составляет 25%.

### Requirement: Проверка формы

Трекер MUST принимать название, только если после `trim` оно непустое.
Часы MUST быть числом от 0,5 до 24 включительно с шагом 0,5. Пустое поле
MUST обрабатываться как отсутствующее значение. При ошибке трекер MUST
показать сообщение рядом с соответствующим полем, сохранить значения формы
и оставить список задач без изменений.

#### Scenario: Пустое название

- **WHEN** пользователь отправляет форму с пустым названием или названием
  из одних пробелов
- **THEN** задача не добавляется, рядом с названием видна ошибка, введённые
  значения остаются в форме.

#### Scenario: Некорректные часы

- **WHEN** пользователь отправляет форму с пустыми, отрицательными,
  нечисловыми часами, значением вне диапазона или значением, которое
  не соответствует шагу 0,5
- **THEN** задача не добавляется, рядом с полем часов видна ошибка,
  введённые значения остаются в форме.

### Requirement: Расчёт прогресса

Трекер MUST вычислять прогресс как округлённое до целого значение
`100 × выполненные часы / общие часы`. Обе суммы MUST рассчитываться
по полному списку задач. Для пустого списка трекер MUST показывать 0 ч
общего времени, 0 ч выполненного времени и 0% прогресса, без NaN или Infinity.

#### Scenario: Удаление всех задач

- **WHEN** пользователь удаляет все задачи
- **THEN** список пуст, общее и выполненное время составляют 0 ч,
  прогресс составляет 0%.

### Requirement: Фильтрация списка

Трекер MUST применять фильтр только к видимому списку. Переключение фильтра
MUST сохранять данные задач и значения сводки.

#### Scenario: Активные задачи

- **WHEN** для стартового примера включён фильтр «Активные»
- **THEN** видны «Практика» и «Повторение», а сводка по-прежнему показывает
  2 ч из 8 ч и 25%.

### Requirement: Автономность и интерфейс

Трекер MUST работать из одного файла `tracker-v2.html` со встроенными CSS
и JavaScript без CDN, внешних библиотек и API-ключей. При ширине 390 px
интерфейс MUST оставаться читаемым без горизонтальной прокрутки.
Поля и кнопки MUST иметь понятные подписи.

#### Scenario: Открытие файла на узком экране

- **WHEN** файл открыт без доступа к сети в области просмотра шириной 390 px
- **THEN** трекер работает, поля и кнопки подписаны, содержимое читаемо
  и горизонтальная прокрутка отсутствует.

## Необязательное улучшение

Если реализовано сохранение в `localStorage`, трекер MUST сохранять изменения
задач и восстанавливать сохранённый список при повторном открытии. При
недоступном хранилище он MUST показать понятное сообщение и продолжить
работу в памяти.

#### Scenario: Хранилище недоступно

- **WHEN** `localStorage` недоступно
- **THEN** пользователь видит сообщение о недоступности сохранения,
  а добавление, удаление и переключение статуса работают в памяти.
