# Данные и расчёты

## Модель данных

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | Уникальный идентификатор | Определяет задачу при удалении и смене статуса |
| `title` | Строка | Хранит непустое название после `trim` |
| `hours` | Число | От 0,5 до 24 включительно, шаг 0,5 |
| `done` | Логическое значение | `true` — выполнена, `false` — активна |

| Название | Часы | `done` |
| --- | ---: | --- |
| Чтение | 2 | `true` |
| Практика | 4 | `false` |
| Повторение | 2 | `false` |

Полный список задач хранится в памяти. Выбранный фильтр хранится отдельно
и определяет, какие задачи показывать. Новая задача получает уникальный
`id` и начальный статус `done=false`.

## Проверка и обновление данных

1. Убрать пробелы по краям названия и проверить, что оно непустое.
2. Проверить, что поле часов заполнено, до преобразования значения в число.
3. Проверить, что число конечное, лежит в диапазоне от 0,5 до 24
   включительно и кратно 0,5.
4. Если есть ошибки, показать их рядом с полями и сохранить введённые
   значения. Добавить задачу только после успешной проверки обоих полей.
5. При удалении или переключении статуса найти задачу по `id`. После
   изменения пересчитать сводку и заново применить текущий фильтр.

## Расчёт сводки

- Общие часы — сумма `hours` всех задач.
- Выполненные часы — сумма `hours` задач с `done=true`.
- Если общие часы равны нулю, прогресс равен 0%. Иначе прогресс равен
  `округление(100 × выполненные часы / общие часы)`.
- Фильтр применяется только при выводе списка и не участвует в расчётах.

| Состояние | Выполнено | Всего | Прогресс |
| --- | ---: | ---: | ---: |
| Стартовый пример | 2 ч | 8 ч | 25% |
| Стартовый пример с фильтром «Активные» | 2 ч | 8 ч | 25% |
| «Практика» отмечена выполненной | 6 ч | 8 ч | 75% |
| Все задачи удалены | 0 ч | 0 ч | 0% |

## Необязательное сохранение

Если используется `localStorage`, сохранять полный список после каждого
успешного изменения и загружать его при повторном открытии. Сохранённый
пустой список восстанавливать как пустой. При отсутствии сохранённых данных
использовать стартовый пример. Если чтение или запись недоступны, показать
сообщение и продолжить работу с данными в памяти.
